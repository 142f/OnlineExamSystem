## 1. 现状盘点

### 1.1 总体形态

~~~
浏览器 SPA (Vue 2, 端口 9202)
      │  /api → webpack-dev-server proxy / Nginx 反代
      ▼
Spring Boot 单体 (端口 9201) ── Interceptor 鉴权(HttpSession)
      │  Controller → Service(接口) → ServiceImpl
      │  Mapper(@Mapper + 注解 SQL) → MyBatis-Plus → Druid 连接池
      ▼
MySQL 8.0 (online_exam, 13 张表)
~~~

- **架构风格**：前后端分离的**分层单体（Layered Monolith）**，非微服务、非模块化。
- **认证方式**：服务端 `HttpSession` + `HandlerInterceptor` 路径匹配鉴权（`RoleAuthInterceptor`）。
- **数据访问**：MyBatis-Plus，**全部使用注解 SQL**（109 处 `Select/Insert/Update/Delete` 注解），无 XML 映射文件。
- **部署**：`docker-compose.yml` 编排 db / backend / frontend 三容器，Nginx 托管 dist 并反代 `/api`。

## 2. 当前版本存在的问题、局限与升级必要性

### 2.1 生命周期：关键组件全部 EOL

| 组件 | 当前版本 | 上游 EOL | 距今 | 依据 |
| --- | --- | --- | --- | --- |
| Spring Boot 2.1 | 2.1.2（2.1 线最新 2.1.18） | **2019-10-30** | 已 7 年 | endoflife.date |
| Vue 2 | 2.7.14（2.7 线最新 2.7.16） | **2023-12-31** | 已 2 年 10 个月 | endoflife.date |
| Node.js 16 | 16.x | **2023-09-11** | 已 3 年 | endoflife.date |
| MySQL 8.0 | 8.0（Docker `mysql:8.0`） | **2026-04-30** | 已 6 个月 | endoflife.date |
| Tomcat 9.0 | 9.0.14 | 2027-03-31（但 9.0.14 距最新 9.0.x 差 7 年补丁） | — | 版本库对比 |

**含义**：EOL 之后不再有 CVE 修复。当前栈里 Tomcat 9.0.14（2018-12）、Druid 1.1.8（2018-02）、mysql-connector 8.0.13（2018-09）、axios 0.18.1 均停留在 2018～2019 年的补丁水平。
**【待核实】** 各组件具体 CVE 编号与影响范围（本轮 GitHub Advisory 接口未返回有效数据，建议升级前用 `mvn dependency-check` / `npm audit` 生成基线报告）。

### 2.2 安全性

已修复的（README 已记录，代码已核实）：BCrypt 密码、Session 鉴权、CORS 白名单、登录限流、越权拦截。

仍存在的：

1. **依赖层漏洞面**：上述 EOL 组件无法获取补丁。
2. **鉴权靠路径字符串匹配**：`RoleAuthInterceptor.isTeacherScope()` 用 `path.startsWith("/edit")`、`"/scores"` 等硬编码判断，新增接口若命名不落在这套前缀里会**默认放行**（`return true` 分支）。这是设计层面的隐患，不是版本问题，但升级时可顺手改造。
3. **全局异常处理器返回固定错误码字符串**（`SYS Request failed with status code 500`），信息量低且与 HTTP 语义脱节。
4. **`/login` 的 `X-Forwarded-For` 未校验可信代理**，限流键可被伪造头绕过。
5. **CORS 白名单默认只放行 localhost**，生产需显式注入 `CORS_ORIGINS`，否则跨域失败。

### 2.3 可维护性

- **JDK 8 语言级限制**：无 `var`、无 `record`、无 `List.of`、无文本块；实体/VO 全靠手写 getter/setter（14 个实体类）。
- **测试栈停留在 JUnit 4**：`@RunWith(MockitoJUnitRunner.Silent.class)`，无法使用 JUnit 5 的参数化测试与扩展模型。
- **前端构建链不可移植**：webpack 3 时代的工具链在 Node 17+ 会因 OpenSSL 3 移除 MD4 而报 `ERR_OSSL_EVP_UNSUPPORTED`（社区已知问题；本项目通过锁 Node 16 规避，而 Node 16 已 EOL）。
- **依赖树不可复现**：无有效 lockfile 版本号，`npm install --force` 才能装上，换机器极易漂移。

### 2.4 性能与体验

| 观测点 | 现状 | 影响 |
| --- | --- | --- |
| 首屏 JS | 600 KB gzip（vendor 单包，Element UI + ECharts 全量打入） | 内网/教学环境可接受，公网首屏偏重 |
| 构建产物 | 12.52 MB，其中 9.79 MB 是 sourcemap | 发布体积与源码泄漏 |
| 构建工具 | webpack 3（2017） | 无持久化缓存、无 ESM 原生、冷启动慢【待核实：本轮无 Node 环境实测】 |
| 数据库 | 13 张表、13 个索引，无外键 | 已有索引优化（README 有 Benchmark），但**无外键 → 一致性靠应用层保证** |
| 连接池 | Druid 1.1.8，`defaultAutoCommit=false` + 自定义 `ExceptionSorter`（把所有 SQLException 视为致命） | 任何一次瞬时连接抖动都可能让连接池自我熔断，健壮性差 |

### 2.5 架构层面的局限（与版本无关的部分）

| 局限 | 说明 | 是否建议改 |
| --- | --- | --- |
| 实体直接作为接口出入参 | Controller 直接用 `Student`/`Score` 接收与返回，无 DTO、无 `Valid` 校验 | 建议逐步引入 DTO + Bean Validation |
| 会话有状态 | `HttpSession` 内存态，**无法水平扩容**（README 也承认限流计数"多实例需换 Redis"） | 单机教学场景**不必改**；若要多实例再上 Spring Session + Redis |
| 路径式鉴权 | 见 2.2 | 建议换 Spring Security 的表达式鉴权或 `PreAuthorize` |
| 无数据库迁移工具 | 手工 SQL | 建议引入 Flyway |
| 无接口文档 | — | 建议 springdoc-openapi |

**B4 的已知坑（本轮已核实的"硬坑"）**：

1. **分页插件必须显式引入 jsqlparser**：`mybatis-plus:3.5.18` 的 POM 中 `mybatis-plus-jsqlparser-4.9` 被声明为 **`<optional>true</optional>`**，而 `mybatis-plus-extension:3.5.18` 的 POM 里**完全没有 jsqlparser**。本项目用了 64 处 `Page<>` 分页，升级到 3.5.9+ 后若不额外引入 `mybatis-plus-jsqlparser`，`PaginationInnerInterceptor` 会因缺少 SQL 解析器而报错。**【待核实】** 该拆分的精确起始版本（业界多认为自 3.5.9 起，建议以官方 changelog 复核）。
2. **Druid 自定义 ExceptionSorter**：`DataSourceConfiguration.CustomExceptionSorter` 实现了 `configFromProperties(Properties)` 与 `isExceptionFatal(SQLException)`。Druid 1.2.x 是否调整了该接口签名 **【待核实】**，升级后需重新编译确认。
3. **Jakarta 命名空间**：仅 4 个文件 9 处 import（`LoginController`、`RoleAuthInterceptor`、`StudentController`、`ProcessContextAware`），改动极小。

## 5. 升级后"效果是否更好"

### 5.1 会变好的

| 维度 | 预期改善 | 可验证指标 |
| --- | --- | --- |
| 安全 | 所有运行时回到受支持版本，可持续接收 CVE 修复 | dependency-check / npm audit 高危告警数 |
| 可维护性 | JDK 21 语法（record/var/文本块）、JUnit 5 参数化测试、ESM 前端 | 新增接口的平均代码行数 |
| 构建体验 | Vite 的冷启动与 HMR 显著快于 webpack 3；产物默认不做全量 sourcemap | `npm run build` 耗时【待核实，需实测】 |
| 产物体积 | Vite tree-shaking + ESM + 按需引入 Element Plus/ECharts | 首屏 JS gzip 大小（当前基线 600 KB） |
| 依赖可复现 | 现代 lockfile（lockfileVersion 3）+ Node 24 | 换机器 `npm ci` 一次成功 |
| 教学/作品价值 | Spring Boot 4 / Vue 3 / Vite 是当前主流技术叙事 | — |

### 5.2 不会变好的

- **业务功能**：完全不增加任何功能（题库、组卷、答题、阅卷、成绩、留言都还是那些）。
- **并发能力**：Session 认证 + 单库，升级后依然不能水平扩容。
- **代码结构**：实体直出、路径式鉴权等问题不会因为升级而消失，需要单独改造。

### 5.3 前提条件

1. **有 2～4 天的可用窗口**（后端 1.5～2.5 人日 + 前端 3～5 人日，含回归）。
2. **有一套可执行的回归清单**（覆盖 3 种角色登录 + 组卷 + 答题 + 阅卷 + 成绩 + 留言）。
3. **构建环境**：JDK 21、Maven 3.9+、Node 22/24、MySQL 8.4（Docker 即可）。
4. **接受"升级期间功能冻结"**：不建议在升级分支上同时加新功能。

> **本轮评估的环境限制**：当前机器 `PATH` 中的 `E:\Project_tools\jdk-23.0.1`、`apache-maven`、`node-v16.18.0` 目录**已不存在**（`E:\Project_tools` 不可访问），本机未安装任何 JDK/Maven/Node，`JAVA_HOME` 指向失效路径。因此**本轮未能实际编译或运行**，所有结论均基于静态代码与上游数据。仓库中 `target/`（Java 8 字节码）与 13 个通过的测试报告为既有产物，可作为"升级前基线"。

### 阶段 2：前端 Vue 2 → Vue 3 + Vite（3～5 天）

1. **脚手架**：保留 `src/` 目录结构（views/components/api/store/router/styles/assets 已是现代结构，可原位迁移），用 Vite 替换 `build/` + `config/`：

import { defineConfig } from 'vite'

import path from 'node:path'

export default defineConfig({
  plugins: [vue()],
  resolve: { alias: { '@': path.resolve(__dirname, 'src') } },
  server: {
    port: 9202,
    proxy: { '/api': { target: 'http://localhost:9201', changeOrigin: true, rewrite: p => p.replace(/^\/api/, '') } }
  },
  build: { sourcemap: false }   // 修正当前 9.79 MB sourcemap 外泄
})
~~~

2. **入口**：`new Vue({el:'#app'})` → `createApp(App).use(router).use(pinia).use(ElementPlus).mount('#app')`。

4. **状态**：Vuex 3 → Pinia（当前 store 仅 1 个模块、3 个 mutation，改造量极小）。
5. **Element UI → Element Plus**（按 4.2 计数逐项处理）：`:visible.sync` → `v-model`（9 处）；`slot-scope` → `#default="scope"`（13 处）；`this.$message` → `ElMessage`（67 处）；`this.$confirm` → `ElMessageBox.confirm`（17 处）；样式引入改 `element-plus/dist/index.css`。

7. **ECharts 4 → 6**：`echarts.init` 用法基本不变，注意按需引入与主题 API 变化。
8. **Docker**：`node:16-alpine` → `node:24-alpine`；dist 路径不变，Nginx 配置无需改。
